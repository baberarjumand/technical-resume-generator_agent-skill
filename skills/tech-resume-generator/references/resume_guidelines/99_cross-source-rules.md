# Cross-source rules

[Index](./00_README.md)

Shared defaults for later resume generation. Per-source notes stay in `01_`–`21_`.

Points that **agree** across UNC samples, MIT CommKit, TealHQ, Tech Interview Handbook, Tiffany Jachja, Yale OCS, LinkedIn Top Content (tech resume roundups), Harvard MCS (College guide — student chrome stripped), r/EngineeringResumes (woodworksio HM + wiki template), Penn Career Services (hub + SCO handout; student chrome stripped), ACI Tech Academy (career-changer IT-support blog — chrome stripped), Emanate Technology (AU recruiter article; their 4-page 2020 PM sample stripped), Rewriting the Code (student/early-career guide; student examples stripped), UT Austin CNS (What/Why/How bullets; student templates stripped), Per Scholas (first-job / career-changer news post — chrome stripped), Georgia Tech Career Center (undergrad hub + Resume Career Guide; student samples stripped), Mastercard Careers (employer tech-resume tips + posted AI rules), Toptal Resume (2025 ATS/keywords commercial guide — product CTA stripped), and IGotAnOffer (FAANG coaching samples — review CTA stripped) — default policy for this repo:

1. **Target the job.** Custom content, section order, and bullet emphasis per application (and per JD keywords). Jachja/O*NET and Yale/NACE: steal impact language when stuck; still prefer the posting’s own words.
2. **One page** for industry SWE unless an academic CV is requested (MIT CV; Yale allows 1–2 pages master’s / 2–3 PhD; Penn FAQ 1–2 pages for professionals / grad guide up to 3 in some industries; UK CVs can run longer; Emanate AU FAQ **1–2 pages** — their own Word sample is **4 pages**, ignore that). TIH + Jachja + Yale undergrad + woodworksio (US HM, 12 YoE, hard 1-pager): one page, ≥0.5" margins, cut anything that does not serve this search. Overflow extras to LinkedIn (Jachja). Drop old roles rather than spilling a second page (woodworksio). Penn undergrad templates also stay 1 page unless alum + advanced degree or substantial work. ACI’s Karla Urbina allows **1–2 pages** for IT career switchers; RTC allows **two** once you have a few years of professional experience; UT CNS and Per Scholas (entry-level) are **hard ~1 page** for jobs; Georgia Tech and Toptal industry résumés allow **1–2 pages** (Toptal: ≤5 YoE stay 1 page); IGotAnOffer / Google How we hire have **no hard length cap** but scold 4–5 pagers and praise Dario’s **1-pager** — still keep **one page** for industry SWE unless an AU recruiter explicitly wants a 2-page CV.
3. **Skimmable in ~20–60 seconds** (UT CNS and Mastercard career-transition cite ~**6 seconds**; Georgia Tech **15–30**; Toptal SWE **6–10** first pass / Goldberg **10 seconds** on the stack line / IGotAnOffer Cody **10 seconds** for YoE — same skim): standard headers, reverse chronological, bullets not paragraphs, named technologies + metrics. Working density: **3–4 bullets, 1–2 lines each** (Yale formatting; woodworksio: 1 line, maybe 2 — 3+ lines means you failed bullets). Jachja allows ≤3 lines / 2–4 bullets. Toptal’s **5–10 bullets** per recent role — don’t; they also say **≤2 lines** per bullet, which matches Yale. Harvard MCS offers a paragraph template; do not use it. Single spacing (woodworksio: double-spacing confuses humans and ATS).
4. **Education first** while still a student / <~3 years (UNC, Yale STEMConnect, TIH, FTL, Harvard College templates, Penn undergrad templates, Georgia Tech CS samples). After graduation / substantial full-time work, **headline summary + skills + experience first**; education drops (Penn hub: move Education below Experience after the current program). Jachja puts **skills at the top** as a recruiter scan layer. Harvard’s CS annotation (“Technical Skills after Education”) and Penn undergrad template #3 are the **undergrad** order. r/EngineeringResumes wiki template: skills → experience → projects → education last. GT **Mary Buzz** OMS sample is experience-first. Woodworksio: skip a professional summary, or **1–2 human-written lines** — keep TIH’s tiny headline, never an AI paragraph. Toptal wants a **2–4 line** summary for ≥5 YoE with **no metrics in the summary** — keep the 1–2 line TIH headline, not a four-line paragraph. IGotAnOffer’s Google page says **skip** summary/objective unless the profile is unusual; Cody’s two recruiter summaries and their senior 3-line para — same skip. Penn grad 2-pager’s 3–5 summary **bullets** are for long/pivot docs, not a 1-page SWE. ACI’s 2–3 sentence “adaptability / customer / AI tools” summary, Per Scholas’ “skills + accomplishments at the beginning” curb-appeal paragraph, Emanate’s “Highly motivated Cloud Engineer with 10+ years…” + ChatGPT summary prompt, and Mastercard’s career-transition **objective** are skip. GT optional Objective / Summary of Qualifications — same skip. RTC: **UK Objective is for UK only — skip on US résumés.**
5. **Quantify with a shared formula.** Yale **WHO** = **APR** = **X as measured by Y by doing Z** = TIH action → outcome = Jachja verb + outcome + tools = Penn **Skill – Context – Outcome (SCO)** = RTC **[Action verb] + [What you did] + [Tech used] + [Measurable result]** = UT CNS **What (product) + Why (time/cost/users) + How (stack + collaborators)** = Georgia Tech **SAIL** (Skill · Achievement · Impact · Learned) / **Task + Skill + Quantity + Result** = LinkedIn **Action + Outcome + Proof** (Ashley Perriman) / **STAR+numbers** (Woolfrey) / **verb + what + how + metric + business outcome** (Talreja) = IGotAnOffer / Google **X, Y, Z** (Bock) / **CAR** as a drafting twin. Include a **baseline** (50→100, 420ms→180ms). Prefer time/cost/users over vanity **lines of code** (UT lists LOC as optional magnitude — skip unless it is a real scale signal). Ban helping verbs (*helped, assisted, worked with, responsible for*) — Penn, Yale, Harvard agree. RTC’s own Google Docs samples still use *Assisted*; GT CS 1 uses “assisted with wireless” — follow the formula, not those bullets.
6. **Action verbs that imply ownership** (designed, led, built, reduced, engineered). Past tense for former jobs; **present simple** (not “creating”) for current. No pronouns (Yale; Emanate’s John Smith sample uses “I” — don’t). Omit generic filler. Don’t paste job-description duties (Emanate article; their template still has a Duties block — follow the article, not the sample).
7. **Skills as 2–3 categorized, scannable lines** — not a 100-item dump and **not** beginner/proficient/advanced **tech** labels. Only list tools you can defend in an interview (Prateek Gogia / Jachja / woodworksio Vue-vs-React). Weave the same names into bullets (Talreja, Connole; Emanate/Mal: “Azure DevOps” without CI/CD vs test vs release is a red flag; Toptal Goldberg: skills listed must appear in experience). Spoken-language fluency labels are OK (Yale, UT CNS technical template). TIH pipes or Jachja commas. Toptal: comma-separated **Core Skills**, up to ~15–20 **true** names, **before** Experience (Jachja order). IGotAnOffer Karl puts skills last and langs in the header — keep langs as a **short header line** if useful, skills still high (their Sam / senior template). Karl’s **Microsoft Office** line — never. No skills **tables**, icons, columns, or vertical laundry lists. Match the JD. Woodworksio: 1–2 highlight lines or omit; never Word/Photoshop. ACI lists communication/organization as Skills — keep those in bullets, not the skills line (Penn/Jachja). Per Scholas likewise wants time-management / leadership **on** the résumé; same skip. UT general template’s “Intermediate Excel / Basic SQL” — don’t copy; their technical template’s “most → least proficient” PL ranking is the same trap. GT undergrad guide allows proficiency “if necessary” and even **skills next semester**; the MS/PhD checklist **forbids** expert/novice — follow the checklist. GT CS analytics lists Word/Excel — never.
8. **Projects prove skill when employment doesn’t**; title + one-line description + 2–3 tech bullets; hyperlink. Drop or shrink when industry already fills the page. Class projects, clubs, and independent work can share a Projects & Leadership section (Yale). RTC: even **one** role-relevant project gets its own section; skip tutorials, undeployed apps, and group work you can’t split. Georgia Tech: classroom projects **only until the first full-time job**. Mastercard: put a **GitHub or portfolio URL** on a tech résumé; project bullets = role + stack + outcome.
9. **Leadership belongs when quantified.** Membership without impact does not. Non-tech / volunteer jobs stay if bullets show transferable competencies (NACE or JD) and numbers.
10. **Contact:** lock the header to the **Critical identity** rules in [00_README.md](./00_README.md) — pull name, location, phone, email, websites, LinkedIn, and GitHub **from the user’s compiled professional data**. All provided contact links must be clickable in the exported PDF (`tel:`, `mailto:`, https). Toptal (Goldberg): GitHub + LinkedIn in the **header**; some recruiters check GitHub **before** the résumé. No street, no photo, no DOB, no pronouns in the body. **Education** lists only schools/degrees the user wants after reconciliation — do not invent schools; omit incomplete transfers unless the user asks to keep them. School email is for current students only (Harvard `@college` / Yale.edu / Penn `@seas.upenn.edu` samples). Harvard fill-in templates and Penn CS/CompE samples still show a street address — ignore street addresses for generated résumés. SAT/ACT only if a finance/consulting posting asks (Penn/Harvard/Yale student chrome) — omit otherwise.
11. **Zero typos.** No contractions/slang (Yale). Plain-text paste test (TIH) plus a human proofread (MIT). Do not copy typos from Jachja’s screenshots.
12. **Author in Word/Google Docs, submit highlightable PDF.** No header/footer content; **≥0.5" margins**; 10–12 pt body, name slightly larger. ATS-safe fonts: Times New Roman, Arial, Calibri, Garamond, Helvetica, Aptos (Emanate FAQ); Toptal also names Tahoma, Georgia, Verdana. Yale’s technical template is Times 10 / name 14, 0.5" margins, 1 page. Harvard’s 2025 College templates are Calibri with ~0.42" side / ~0.19" bottom margins and no tables; their “Accessible” Word twins use **tables** — do not copy the table layout. Penn hub: 1" to 0.65"; undergrad Word pack **0.6"** — that sits above the 0.5" floor. Keep the 0.5" floor. Penn PhD samples put name+page in a header/footer; Brasch ATS blog and TIH say **don’t** — skip headers/footers on the 1-pager. Name the PDF with your name (Penn, UT `Last_First_Resume`). Per Scholas / GT also allow **position or company** in the filename — optional; don’t unique-file every posting. UT ATS page: no tables, columns, graphics, **LaTeX**, or Canva. Grissett “no premade templates” and GT “don’t use Microsoft Word or Canva templates” mean designer/stock packs that ATS mangles — keep Word/Docs (their own samples), not Canva. GT: **0.5–1"** margins, **11–12 pt**; keep the 0.5" floor. Toptal ATS article prefers **.docx** for parsers; SWE sibling says **PDF unless asked** — keep author-in-Docs, submit highlightable PDF unless the portal wants Word. Toptal SWE “skip bold/italic” is over-cautious; consistent bold for names/stack is fine (Yale/UT). IGotAnOffer: Arial/Calibri 10–12, black and white, PDF; Dario’s **green titles** and two-column skills — skip (Candace: columns break ATS).
13. **AI tools:** start from an original draft (Yale OCS, Harvard MCS, woodworksio). Use AI to extract JD keywords, critique, or research the company; do not paste generated prose — this HM **auto-rejects** AI-written résumés and cover letters. ACI CareerConnect, Emanate’s ChatGPT prompts, and Per Scholas **ResumeBoost** (Agentforce first draft from coursework) *do* pitch AI-drafted sections; do not follow that for this skill’s output — rewrite every AI-suggested bullet from real facts. Georgia Tech’s GenAI 8 prompts are closer to Yale/Harvard (keywords, polish, ATS critique) — still **rewrite** any bullets Prompt 3/6 generates. RTC: don’t paste ChatGPT without rewriting; don’t list ChatGPT as a skill — Netflix/Clay want **verified** AI-in-the-workflow bullets. Employers may scan for AI and some post **AI-use rules** — follow them; disclose if asked (Harvard). **Mastercard** ([AI guidelines](https://careers.mastercard.com/us/en/ai-guidelines)): AI may help **word** a résumé if every fact is real; cover letter = own voice (grammar OK); **no** AI-generated answers in live interviews; technical-assessment AI only if they invite it. Falsifying skills (with or without AI) is a disqualify. UNC 2026 templates treat Copilot/OpenAI as listable skills with quality control — include when true. Strip identifiers before sending a resume to a public AI tool. Harvard Big Resume / Yale Big Interview are school-gated feedback tools, not authors. Toptal’s ATS score checker is a **product diagnostic**, not an author — same skip. Toptal cites FT (~half of applicants use ChatGPT) and Big 4 caution: **generic AI prose gets dismissed** — agrees woodworksio. Greenhouse/Lever do **not** secretly AI-auto-reject PDFs (woodworksio, PhenomEng); knockout **application questions** and human skim do.
14. **Do not invent certifications or tools.** Only real credentials. Listing a JD keyword requires real exposure (Jachja) — build a project if needed, don’t fake it.
15. **Apply widely, not sloppily.** Volume across companies is fine (Jachja). Do **not** spray unrelated roles at **one** company (TIH; woodworksio/PhenomEng can see every apply in the ATS). Luca Francis (Emanate): don’t spray every posting hoping one sticks — tailor or skip. Fill employer forms as carefully as the PDF. Do not lie about work authorization / sponsorship (woodworksio).
16. **Match template to narrative:**
    - SWE intern/frontend lead path → UNC Template #1
    - Data/ML/platform → Template #2 or #5
    - Post-full-time / research-adjacent → Template #3 (industry + research split)
    - Thin CS formal education, strong projects → Template #4
    - Yale STEMConnect skeleton = student STEM (education → skills → work → projects); do **not** use that order for experienced industry candidates
    - Harvard College Tech example = CS intern (education → skills+class projects → internships → leadership); Engineering example = research-first, skills last. Do **not** use either order, or Harvard’s high-school / SAT / hobbies / street-address chrome, for experienced industry candidates
    - r/EngineeringResumes wiki Google Doc = experienced US skeleton (skills → work STAR/XYZ/CAR → projects → education); woodworksio 15-point scan rules on top
    - Penn undergrad template #3 (GitHub + Technical Skills + Projects) + CS sample = student intern (education-first). CompE sample uses fluency labels — don’t copy. Bioengineering / CBE PhD samples = academic 1–2 pagers. Skip Penn street addresses, school email, SAT (finance/consulting only), high school, and interests
    - ACI Tech Academy = CompTIA / help-desk career changer (skills-based, certs-in-progress, 2–3 sentence AI-friendly summary). Not a SWE template. Keep Karla’s ATS bits that already match 99: no colors/photos/columns, no street, tailor the JD, quantify non-tech work only if a bullet earns its line
    - Emanate Technology = AU recruiter (CV, 1–2 pages, Word/Docs, quantify, name the stack in the bullet). Their 2020 John Smith Word file is a 4-page public-sector **PM** duty-CV — do not clone. Cover letter only if an AU process asks; hobbies stay off
    - Rewriting the Code Google Docs pack = student/MS intern examples (education-first, Radha ~2p / Aesha 1p). Canva twin is view-only — skip both layouts. Keep Swadha’s jumbo doc + role-family variants and the verb+tech+metric formula
    - UT Austin CNS Technical Google Doc = CS intern (education → skills → experience → projects). Use What/Why/How bullets; nested titles at one employer; bold languages/platforms only. Do not clone Bevo fill-in, school email, or PL proficiency ranking
    - Per Scholas = first-job / IT-support career changer (Grissett 2024). Keep ~1 page, JD keywords, skills near the top, PDF. Skip soft-skill dumps, classes/unrelated jobs as filler, ResumeBoost drafts, and a unique file per posting
    - Georgia Tech Career Center = undergrad hub (education-first CS Word samples) + MS/PhD checklist. Use **SAIL** / ATS no-tables / 0.5–1" / PDF. CS 1 = intern. **Mary Buzz** OMS sample = experience-first (closest GT analog) — strip proficiency labels, knitting, street/ZIP. Cover letter only if asked (their guide says always attach — don’t)
    - Mastercard Careers = employer tech-resume tips (Jul 2023): tailor, JD keywords where true, quantify, skills section, GitHub URL, adaptability bullets. No layout. Career-transition 80/20 + objective is pivot-only. If applying there, follow their AI guidelines and be able to defend every line
    - Toptal Resume = commercial 2025 ATS/content guide (Close + Goldberg). Keep reverse-chrono, Core Skills **before** experience, quantify, GitHub in header. Do **not** use 5–10 bullets, 2 pages, a 4-line summary, 25–30 stuffed keywords, or their ATS checker as an author. No template to clone.
    - IGotAnOffer = commercial FAANG coaching (Parry + Cody/Candace). Keep Dario’s 1-page nested quantified bullets, Sam’s skills-at-top, Google langs-in-header, XYZ. Do **not** clone 4–5 pagers, Karl’s Office line, green ink, street addresses, or the paid review CTA. Google How we hire: no cover letter required.
    - Experienced FAANG-style SWE (roughly 3+ YoE full-time, especially lead/staff/founder) → TIH + Jachja order, Yale WHO / Penn SCO / X-Y-Z bullets: **headline summary → contact → skills (2–3 categories) → work experience (verb + metric + tools) → education → selected projects/certs**, one page, JD-keyworded. Keep at most a few role-family variants (woodworksio: Leadership / ML / Fullstack), not a unique file per posting. Penn’s “master résumé then cut” is a drafting aid, not a second submitted page
    - Cover letter (only if requested): Harvard 3-paragraph skeleton, named addressee, colon after Dear, same font as the resume, 1–2 quantified examples, do not rehash the whole résumé. Woodworksio: skip unless it adds a real extra (domain, clearance, constraint); never AI-generate it
