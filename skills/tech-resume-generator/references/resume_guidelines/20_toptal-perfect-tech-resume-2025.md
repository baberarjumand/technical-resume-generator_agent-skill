## 20.1 Primary — 2025 structure

**Market pitch:** ManpowerGroup Q2 2025 IT hiring outlook 35%. Recruiters want **outcomes**, not duty lists. ATS scans keywords **and** structure. Columns/tables/heavy styling fail.

**Trends:** metrics in bullets (“increased system efficiency by 25%”); soft skills **shown** (mentoring, sprints, docs) not listed; **2–4 line summary** if **≥5 years** — technical focus, **no metrics in the summary** (those go in experience). Name stack + scale (React, Kubernetes, Django, AWS). Goldberg: recruiters skim for **tech-stack alignment**. No emojis, graphics, unusual fonts.

**Sections (familiar order)**

| Section | Rules |
| --- | --- |
| Header | GitHub + LinkedIn **standard** for engineers |
| **Professional / executive summary** | ≥5 YoE; short paragraph; specific; no filler. Director+ = “executive” |
| Work | Reverse chrono; **5–10 bullets** recent roles, fewer on old; present/past tense; drop off-path jobs; results not tasks |
| Education | Degree, school, year optional; short if degree **>5 years** old; GPA only if high, recent, relevant |
| **Core Skills and Certifications** | **Up to 20** role-relevant tools, **comma-separated**. Only skills **also in bullets**. Certs inline or a short block. Keyword hub |
| Optional | Volunteer/affiliations 1–2 lines, **no bullets**. Pubs/awards/PD if relevant. **No hobbies or references** |

Goldberg: she often decides in **10 seconds** from how clearly the stack is presented.

**Pro tip (this page):** put **Core Skills before Work Experience**.

**Format:** reverse chrono only (no hybrid/functional). No objective. **≤2 pages**; length isn’t the point — cut fluff, one-line bullets where possible, don’t shrink fonts to cram. Don’t exceed **two lines** per bullet. Fonts: **Calibri, Tahoma, or Georgia**. Plain: no tables, columns, emojis, fancy graphics. Spell out large money (`$3 million` not `$3M`).

**Keywords:** Gartner 2025 — same terminology as postings. Where + how often + alignment. Repeat JD terms in Core Skills, bullets, **and** summary. 15–20 targeted skills.

## 20.2 SWE sibling (Kingo)

- ≤**5 years** → **one page**; more senior **may** go two
- Recruiters **6–10 seconds** first pass
- Single column; Calibri/Georgia; **skip bold/italic** (over-cautious vs Yale/GT scan rules)
- PDF unless the posting says otherwise
- Summary 2–4 lines, e.g. Go/Python/AWS APIs, cost + pipelines
- Core Skills **10–20**, grouped (front/back/DevOps); GitHub in header **before** they read the file
- Current role **5–10** bullets; older fewer. Verb + result + tool: “Reduced CI/CD build time by **70%** by implementing parallel testing with CircleCI and Docker.” Don’t dump a tech list in the bullet
- Omit grad year if **>5 years** (age bias)
- No hobbies, soft-skill list, objectives, photos, references
- Proofread

## 20.3 ATS + mistakes + alignment siblings

**ATS screening:** Fortune 500 ~90% use ATS (academic cite). Accenture/HBR: 80% of execs said **>half** of high-skill applicants were ATS-disqualified — vendor-adjacent; don’t treat as auto-reject physics (woodworksio/PhenomEng). Failures: headers/footers/graphics/text boxes/tables/columns; decorative fonts; **.docx preferred**, PDF only if text-layer; nonstandard headings (“Projects” vs “Experience” — **over-cautious**, keep Projects if you have them); missing JD keywords. Keyword **variations** (React + JavaScript frameworks). Soft skills only tied to outcomes. Job title near the top. **AI-written résumés:** FT ~half of applicants use ChatGPT; Deloitte/EY/PwC/KPMG caution grads; **generic AI prose gets dismissed**.

**Mistakes:** vague “web stack” vs React/Node; don’t repeat JavaScript in every bullet; don’t title yourself “Software Expert”; drop **>10-year** clutter; “responsible for” banned; every bullet answers *what did I improve, build, or solve?*; plain-text paste; freelance labeled; cut Flash/VB.NET unless asked; only list tools you’d use **today**.

**Misalignment:** one résumé for many roles fails. Goldberg: if title/skills/keywords don’t jump out in **seconds**, she moves on. Checklist they pitch **25–30 JD keywords** — **don’t stuff**; use true terms. Mirror industry titles (DevOps / SRE not “technical specialist”). Internal jargon out.

**Summary guide:** 2–4 lines; **not** an objective; third person, no “I”; HBR first **15–20 words**. Don’t keyword-dump the summary. SWE example is closer to TIH than their QA/PM samples.

## 20.4 Tensions / experienced candidate

| Toptal | Repo default |
| --- | --- |
| 1–2 pages (even senior) | **One page** (woodworksio/TIH, 12 YoE HM) |
| 5–10 bullets per recent role | **3–4**, 1–2 lines (Yale/woodworksio) |
| 2–4 line summary (≥5 YoE); metrics **out** of summary | TIH **1–2** human lines; woodworksio skip or tiny. Keep a short **headline**, not a 4-line paragraph |
| Up to **20** comma-separated skills | 2–3 **category lines**; 20 names can fit if they’re all true and in bullets |
| Core Skills **before** Experience | Agrees Jachja. Ignore the ATS article’s “skills at the end” |
| Skip bold/italic (SWE) | Use consistent bold for names/stack (Yale/UT) |
| Prefer **.docx** for ATS | Author Word/Docs; **submit PDF** unless the portal asks .docx |
| `$3 million` not `$3M` | Numerals + units OK if unambiguous |
| Don’t use a **Projects** heading | Keep Projects if industry doesn’t fill the page |
| 25–30 JD keywords | True keywords only (Jachja); stuffing is a fail |
| Unique file per posting | Few role-family variants + keyword pass |
| Omit graduation year >5 years | Optional (age bias); education dates can stay if useful |
| Toptal ATS checker | Optional diagnostic; not an author. Don’t paste ChatGPT |

**Template match:** closest to TIH + Jachja + r/EngineeringResumes wiki: **headline → contact (GitHub) → Core Skills → reverse-chrono work (verb + metric + stack) → education**. Strip the 5–10-bullet density and 2-page allowance. Goldberg’s stack-skim and “focus beats breadth” match 99.
