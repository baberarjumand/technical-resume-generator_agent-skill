**Stated problem:** First-time tech résumés are either **vague** or **stack-only**. Recruiters want someone who (a) can code, (b) can communicate/work with teams, (c) is driven by **impact**.

Weak examples they kill: “Wrote production-level code”; “Built an app”; “Programmed game in Java”; “Built a web-app using React for frontend and used MongoDB for backend”; “Implemented REST API using DynamoDB, Python, and Serverless.”

## 16.1 What / Why / How (software projects)

Three recruiter-impressing pieces. They can live in **one** bullet or split across bullets.

**What** — not “mobile app”; what it **does**.  
“Developed a mobile app to connect doctors and patients during rehabilitation to optimize surgical outcomes.”

**Why** — time, cost, usage, or magnitude:

- Time saved (dev or client)
- Infra / client cost
- Users / teams
- Magnitude: LOC, data volume, API endpoints, unit tests / coverage  

Example: “Reduced pipeline development time from **weeks to days** for **10+ teams** to aggregate supply and demand signals for pricing.”

**How** — stack **and** people:

- Languages, technologies
- How many engineers
- How many PMs/clients  

“Collaborated with **4 engineers** to build a Texas RoboCamp attended by **50+** high school students annually.”

**Five “strong” examples on the page**

1. Waves app for cancer/mental-illness patients (music therapy) — product *what*
2. Forum for **40,000** students
3. NLP summarizer: ESPN **4 pages → &lt;4 sentences**
4. Collaborated with UI/UX (Figma) + backend via Git for stakeholder features — *how* / teamwork
5. Research with **10 nurses** + robotics team; Moxi UX for **3 hospitals**

**NDA internships:** talk to supervisor/mentor about what can go on the résumé. The linked Kickresume article is dead; keep: describe **function + stack + public impact**, not secret product names or confidential numbers.

## 16.2 Hub formatting / ATS / content

**Format (Formatting page):** 10–12 pt, never &lt;10; margins **≥ 0.5"** (print); **1 page** for jobs/internships; master file of everything (any length) for grad/professional school; named `Last_First_Resume.docx` / PDF; human proofread.

**ATS:** ranks vs JD. Tailor: list JD keywords by frequency, then weave **true** ones. **Chronological only** — no functional résumés. Avoid **tables, columns, graphics, objects, LaTeX, Canva**. Use their Word/GDoc templates. (Tension with Source 04 Overleaf catalog — don’t ship LaTeX to ATS portals.)

**Content:** employers ~**6 seconds**. Formula in their video: **strong action verb + how you did it + impact**. Expand acronyms. High school gone by **start of year 2**. JobHero for same-title bullets only.

Weak → strong (student org): “Responsible for organizing events” → quantified panels (25–50 undergrads, bi-monthly), outreach to professionals, Instagram/flyers → **500** attendees / **$10,000** raised.

CS example on Content: “Redesigned Internet and intranet pages (Java, C, C++, and HTML) and used SEO… improved functionality of company database.” (Stack-heavy; weaker *why* than the technical-bullets page.)

**Overview FAQs**

- Two roles at one org → **one employer block**, nested titles (Fundraising Chair vs member; Research Mentor over RA)
- Color: usually **no** (ATS + skim). Black text
- Custom LinkedIn URL (`linkedin.com/in/jane-smith`); omit LinkedIn if the profile is empty
- Transfer school: optional; “Completed basic coursework”; **no degree name you didn’t earn**
- Repeat summer jobs: “Summers 2019 & 2020”
- Projects: `built (app) using (tools) to do (what it does)`. Twitlist: Spotify playlist from Twitter hashtags — Flask, Mako, Requests, Spotify/Twitter APIs
- Bold **only** languages / platforms / hard skills, consistently — never soft-skill words

## 16.3 Template reverse-engineer

**Technical (CS/DS)** — 1 page, education-first intern skeleton:

| Order | Notes |
| --- | --- |
| Contact | Phone, **@utexas.edu**, **github.com/…**, LinkedIn, **Austin, TX** (no street) |
| Education | GPA ≥ 3.0 to 2 decimals; optional minor/certificate; **couple** relevant courses |
| **Skills** (before Experience) | PLs **most → least proficient**; Technologies (Git, React…); spoken-language fluency labels; optional certs |
| Experience | Reverse chrono; 3 bullets: verb + task + result; pointer to this strong-bullets page |
| Projects | Optional; **move above Experience** if more relevant. `NAME \| langs/APIs` + outcome bullets |
| Leadership & community | Optional |
| Honors | Optional; 1–2 honors → fold into Education |

**General** — no GitHub; Skills **last**; Technical/Computer Skills with **Intermediate Excel, Basic SQL** (Jachja/woodworksio reject tech proficiency labels).

Both are student order. Technical’s **skills-before-experience** is closer to Jachja than Harvard CS “skills after education,” but still education-first.

## 16.4 Tensions / experienced candidate

| UT CNS | Repo default |
| --- | --- |
| 1 page jobs; long **master** for grad school | 1 page; master is a drafting aid (Penn/RTC/Swadha), not a second submitted page |
| Unique file **per posting** | Few role-family variants (woodworksio) + JD keyword pass |
| LOC / test-count as “magnitude” | Prefer time/cost/users/baseline. Skip vanity LOC |
| Technical template: PL proficiency ranking | No beginner/proficient/advanced **tech** labels |
| General template: Basic SQL | Don’t |
| Education first | Education last |
| School email, Austin city | Personal Gmail; city/country OK |
| ~6s skim | Same family as 20–60s; still one page |
| No LaTeX/Canva/tables/columns | Agrees TIH/Penn; ignore Overleaf for applications |
| Nested titles at one company | Keep |
| Bold only hard skills | Optional; don’t over-bold |
| NDA: ask the company | Agrees — don’t invent details |

**Template match:** CNS Technical ≈ UNC intern / Penn template #3 / RTC student (education first, GitHub, skills high, projects movable). Use the **What/Why/How** bullets, not the Bevo fill-in order.
