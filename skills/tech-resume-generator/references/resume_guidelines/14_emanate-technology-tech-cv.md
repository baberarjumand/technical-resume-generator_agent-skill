## 14.1 Article writing rules (Jan 2025)

**What a “tech resume” is (vs a duty list)**

- Results: metrics (“+20% traffic”, “−15% downtime”)
- Skills: make the **stack** obvious for this job
- Projects (work, personal, OSS) prove ability and interest

**Structure they name**

1. **Professional introduction** — 1–3 sentences, tailored, core experience + strengths. Example is generic “Highly motivated and results-driven Cloud Engineer with 10+ years…”
2. **Skills** — a “shopping list” is OK in tech (they contrast other industries)
3. **Achievements in Experience** — “where most applicants go wrong.” Quantify. Do **not** paste the job description. Unique contributions + impact. Example: “Led … new cloud-based infrastructure, **20%** lower opex and **30%** better performance.”

Throughput example they prefer over soft-skill claims: “Within six months increased the software development team’s throughput by **70%**” vs “strong time-management and problem-solving.”

**Tailor** every application; recruiters buy a **solution to their problem**.

**Format / ATS**

- Fonts: Arial, Calibri, or Times New Roman **10–12 pt** (FAQ also names **Aptos**)
- Consistent spacing, clear headings
- Bold/italics/bullets for hierarchy
- **Word or Google Doc**, simple layout. Avoid excessive **tables, columns, images**
- Keywords: languages, cloud, data/ML, cyber, Agile/Scrum/CI/CD — **only if true**. Quality over dumping every language. Soft skills via **examples**, not a label (STAR prompt in the article)

**“Not all about IT”** (especially **management** roles): stakeholder management, leadership, problem-solving with definite examples. They also invite **hobbies / personal projects / PD** to show enthusiasm — tension with TIH “skip hobbies.” Keep projects; skip hobby lists.

**Checklist:** proofread; consistent format; tailor; quantify; soft skills *alongside* tech.

**FAQ**

1. Length: **1–2 pages**; “a few seconds” of attention  
2. AU CV: same bones as elsewhere + “location-specific language” (they don’t actually list AU vs US differences beyond that) — FAQ #2 is duplicated in the HTML  
3. Cover letter: **“Absolutely!”** personality, motive, values fit  
4. Template at `/resume-template`  
5. Gaps: honest one-liner + skills gained (freelance, projects, volunteer, study)  
6. Uni results: recent grads / thin experience only; **experienced = work wins**  
7. Don’t list every technical skill — JD-relevant only  
8. Fonts as above; no decorative fonts  
9. Stand out = quantify + unique skills/projects + tailor + keywords + evidenced soft skills  
10. Mistakes: typos, irrelevant content, generic duties instead of impact

**AI prompts they publish** (generate summary, 3 bullets, rephrase to JD keywords, 20 AU keywords, 20 ATS keywords from a JD, STAR soft-skill examples). Same family as ACI CareerConnect — **draft**. Repo default remains editor-only (woodworksio auto-reject).

## 14.2 Recruiter siblings (Luca / Mal / Florent)

**Luca Francis** (why no interviews, Jul 2026): often the CV doesn’t **make the match obvious**; HMs won’t read between the lines. Saturated roles = dozens–hundreds of applicants. Fixes: projects delivered + **technologies used** + **outcomes**; tailor so key skills are easy to find; “one size fits all never has as much success”; don’t bury achievements or leave career-history questions; **don’t spray every posting**; follow up recruiters; keep LinkedIn current.

**Mal Konfu** (how they score CVs, Apr 2026) — invert for writing:

- Green: ownership verbs (*led / designed / implemented*) **with context**; similar programs/stacks (can start fast); impact not tool names alone; stakeholder story
- Red: titles + duties only; long tenure with no depth; “experience with Azure DevOps” and no CI/CD vs test vs release; **only** obsolete platforms. Certs (even in progress) as a *signal* of currency — don’t fake them
- Keywords without depth fail the call. Gaps are normal for **contractors**. Job-hopping is no longer an automatic red flag
- Non-technical reviewers need **what you used and how** spelled out

**Florent** (redundancy, Aug 2026): in days 1–3 write down 2 years of numbers (migrations, incidents prevented, platforms, cost, shipped product, teams, uptime). Week 1: dates, summary, new achievements, **skills easy to spot** — don’t turn the CV into a month-long project. Then LinkedIn + recruiters.

2016 Canberra list is historical demand (EA, cloud/scripting, Dynamics, security, Agile/Prince2 blend) — useful only as “AU gov still likes named frameworks,” not as the candidate’s skill dump.

## 14.3 Word template reverse-engineer (Feb 2020)

Filled **John Smith**, ICT **Project Manager**, Canberra / Federal Government flavour. **4 pages** despite the article’s 1–2 page FAQ. US Letter, not A4. No tables. Orphan 18×18 PNG in the package, unused.

| Block | What’s there |
| --- | --- |
| Contact | Name, Mobile, Email. **No city, LinkedIn, GitHub, street** |
| Overview / Summary | **Five** labeled prose chunks (PM, ICT professional, stakeholder, reporting, leadership). First person (“I successfully…”). ~10 years, teams of 30, named vendors |
| Skills Summary | **16** mixed lines: stakeholder engagement, PMBOK/Prince2/Agile/Waterfall, ITIL, leadership, “high level report writing,” plus a few tech-ish items |
| Tertiary Qualifications | **Before Experience**: MPM (current), Grad Dip 2014, BIT 2000 |
| Experience | Company one-liner, then **Key Duties/Responsibilities** (duty lists), then **Achievements** that repeat “on time and on budget” / “won an award” |
| Other Quals | CIT diplomas, ITIL, CCNA, Lotus, VMware SRM, **AGSVA Baseline** clearance |
| Technical Skills | Vertical dump: Wintel, AD **2003/2008**, NetBackup 5.x–7.x, Exchange 2007/2010, Office **1997–365**, Server 2003–2012 (last line duplicated) |

Typos in the sample: “130 severs”, “30,000 uses”, “Company E” twice.

**The template fights the article:** duty lists, generic achievements, 4 pages, first person, education-before-work, obsolete-only stack (Mal’s red flag), soft skills as a shopping list *and* in the summary, no LinkedIn. Treat it as an **AU public-sector PM** artifact from 2020, not a 2025 SWE spec.

## 14.4 Tensions / experienced candidate

| Emanate | Repo default |
| --- | --- |
| AU **CV**, 1–2 pages (article); template **4 pages** | US SWE **one page**. AU applications may go 2 pages if a local recruiter asks |
| 1–3 sentence “Highly motivated…” profile + AI to write it | TIH 1–2 human lines; no AI paragraph |
| Skills shopping list (article) + 16-line + tech dump (template) | 2–3 categorized lines; weave tools into bullets (Mal agrees: tools need *how*) |
| Cover letter “absolutely” | Skip unless requested (woodworksio). AU agency process may still want one |
| Hobbies OK | Skip; personal **projects** stay if they prove skill |
| Education before experience (template) | Education last |
| Duties then Achievements | Achievements-only bullets (SCO/WHO). Drop “Key Duties” |
| First person | No pronouns (Yale) |
| Word/Docs, no tables/columns/images, 10–12 pt, 0.6–0.7" margins | Agrees. Aptos OK |
| AI-generated bullets/keywords | Editor only |
| Uni marks for juniors | Skip |
| Gaps: one honest line | Agrees |
| Clearance on the CV (AGSVA) | Only if real and the AU/gov role needs it |

**Template match:** none for the candidate’s SWE/lead page. Closest *advice* is Luca/Mal: make the match obvious, name the stack **in the bullet**, quantify, tailor. Do **not** clone John Smith (PM duty-CV, 4 pages, 2003-era tools, first-person summary).
