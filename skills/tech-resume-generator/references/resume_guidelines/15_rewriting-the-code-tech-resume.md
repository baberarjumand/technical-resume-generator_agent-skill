## 15.1 Article writing rules

**UK vs US:** UK/I CVs get an **Objective** (few sentences: goals + why this org). **Not recommended for US.** (Agrees TIH skip-summary for US; contradicts Emanate’s 1–3 sentence AU intro.)

**Education** (even if the degree is unfinished): school, degree + major, expected grad, **GPA only if ≥ 3.0**, relevant courses tied to the job, certifications.

**Experience:** ~**3 bullets** of accomplishments (more/fewer OK). Action verb + tech + metrics.

**📌 Formula:** `[Action verb] + [What you did] + [Tech used] + [Measurable result]`

Weak → strong: “worked on a team project to build an internal tool” → “Designed and implemented an internal dashboard using **React and Node.js**, which reduced manual reporting time by **over 50%** for the operations team.”

**Skills:** languages, software, platforms. **No soft skills here.** Short, bulleted. Only tools you’re comfortable using for *this* job.

**Leadership:** staff recruiters call it **vital** for this audience. Show soft skills via action (workshop, led a team, mentored). Volunteer/extracurriculars with dates, projects, offices. **Always list RTC membership** (signals PD/community; fellow members in interviews). N/A for an experienced candidate.

**Tailor:** Swadha Rai — keep a **jumbo** master doc and swap sections. She keeps **role-family** versions (fullstack SWE, backend, frontend, DA, DS). Match courses, skills, and experience bullets to the JD. Agrees Penn master-résumé + woodworksio few variants.

**No experience / pivot:** Projects section — solo, with friends, or school. GitHub, Replit, personal site. Stats are a bonus, not required.

**Graveyard (don’t):**

- Generic / not tailored to you
- Paste ChatGPT without personalizing
- Length: **one page**; **two** if you already have a few years of professional experience. Recruiter skim ~**30 seconds**
- Over-design (ATS / “AI” parsers fail on fancy layouts)
- Every tool you ever touched
- Passive voice

## 15.2 Projects sibling (Apr 2026)

Own section if the work maps to the role — even **one** project. Same formula.

**Counts:** personal projects with users/impact; hackathons (win optional); academic work from ~the last year; **substantial** OSS (not typo PRs); freelance/volunteer; forks with real changes.

**Doesn’t:** tutorials; undeployed apps; generic clones; group work you can’t split; anything you can’t discuss in depth.

Pick projects at the overlap of a **real JD** and a **problem you actually had**.

Interview: short pitch (what it is, skills for this role, outcome). Don’t recap the résumé. Don’t ramble 10 minutes unless they ask.

## 15.3 AI skills sibling (Jul 2026)

RTC Pulse (Dec 2025): 57% of members use AI daily at work; 44% got no employer training. Recruiters at **Netflix** and **Clay**: the skill is **judgment**, not the tool. Both run **tool-agnostic** AI evals in interview.

Resume:

- Don’t list “ChatGPT” as a skill bullet
- Outcomes + judgment calls, not tool names
- Weak: “Used ChatGPT for research and writing”
- Stronger: “Used AI to accelerate research synthesis, then **verified outputs against primary sources** before incorporating into final deliverables”

Treat AI as a first draft; know enough to catch confident errors. Aligns woodworksio/Yale “don’t paste generated prose” and Jachja “only list what you can defend.”
